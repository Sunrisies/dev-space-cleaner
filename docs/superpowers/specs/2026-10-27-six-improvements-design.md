# 六项体验改进

用户已要求按照此前提出的顺序依次完成六项；每一项需单独验证，完成后继续下一项。

1. 全局缓存作为独立扫描范围，默认关闭，选择工具后单独扫描；项目结果与全局结果不混算。只识别验证过的缓存子目录，显示共享下载缓存、重建和联网影响。清理前重新校验原始规则与目录身份，使用系统回收站，失败不永久删除。保留旧扫描设置。常规 npm、pnpm、pip、Gradle 和 Go 路径分别按平台识别；不可验证的自定义路径明确说明，不执行项目脚本。
2. 按项目路径聚合结果，显示每项与项目总额，支持磁盘、大小和目录修改日期筛选。筛选不改变总体汇总；修改日期不是最后使用时间，嵌套目录不得重复计量。
3. 清理确认逐项展示规则、重建／重下载、共享范围与统计状态；不可确认身份或不完整的候选保持不可选。提示基于规则，不推断文件占用进程。
4. 历史结果默认关闭，保存时间、范围与各条状态；重启后显示为历史数据，不允许直接清理。新扫描和单项刷新先经后端重新识别、完整测量并登记当前会话。缓存失效与文件变化不能当作文件系统快照。
5. 清理历史仅记录用户明确执行的操作、路径、大小、时间与逐项结果；本地存储，写入失败明确提示。提供打开系统回收站入口，不承诺可恢复；不恢复或清空回收站。
6. 调查现有 Windows / macOS CI 失败并修复可复现问题，执行可用构建和测试，记录 Apple Silicon / Intel、打包、回收站和权限验证覆盖。没有 Mac 实机或签名凭据时不能声称相应测试／发布已完成。

交互沿用紧凑窗口，主页面不出现外层滚动，列表和弹窗内容独立滚动；所有磁盘默认项目扫描与已保存设置继续有效。所有测试只使用专门生成的临时文件，绝不清理真实用户缓存。

## 当前进度

第 1 项：已接入独立全局扫描、按工具汇总、设置保存、影响提示和清理前重验。只识别常规目录，不执行工具命令；自定义缓存位置、Xcode DerivedData 和其他下载仓库仍未覆盖。Windows 临时目录样例、工作区测试及 UI 场景已验证；Unix 链接样例需要在 Unix 环境运行。

第 2 项：目录／项目视图可切换，项目分组保留每项详情与右击菜单，支持组内批量选择；按磁盘、大小和目录修改日期筛选不改变整体汇总。分组按候选的归属目录计算，Bundler 例外使用项目目录，不猜测跨目录 workspace。大小筛选只包含已完整统计项目。

第 3 项：确认对话框按每个规则显示重建、依赖重装或共享缓存影响。进入确认前通过后端校验当前会话、目录身份及识别依据；异常候选显示原因并阻止确认。执行清理时仍独立重验，不能把预检当成文件系统快照。

第 4 项：历史结果默认关闭，可在设置中开启；保存至本机应用配置目录，显示原扫描时间并标记历史状态。历史目录不会登记为可清理候选；单项刷新重新识别和完整测量后才可选，刷新失败继续禁用。历史记录超过 20 MiB、损坏或保存失败时提示，保留原文件。

第 5 项：清理后在本机应用配置目录保存最近 1000 项时间、路径、逻辑大小、类别及成功／失败信息；记录损坏或写入失败时保留原文件并提示，不影响已发生的清理结果。界面提供搜索和打开系统回收站入口；Mac 打开当前用户的 Finder 废纸篓，实机效果待验证。

第 6 项的前期诊断：首次 GitHub Actions 中 Windows 和布局任务成功，两个 Mac 任务在 clippy 阶段失败。Apple Silicon 日志显示 `crates/cleaner-core/src/platform.rs` 的 macOS 分支触发 `clippy::collapsible_if`；详细修复及两架构重验仍未进行。
