# 缓境：开发依赖与构建目录清理工具

日期：2026-10-17

## 目标与技术选择

提供面向 Windows、macOS 的中文桌面工具，扫描 Node.js 的 node_modules、Rust 的 target、Python 的 .venv，展示体积，由用户选择后移入系统回收站。

采用 Tauri 2 + React + TypeScript，Rust 扫描引擎是独立 crate，不依赖 Tauri。开发与测试工具可直接调用核心引擎，以区分文件系统成本与界面成本。

GPUI Kit 是可行的替代界面方案：官方列出双平台支持、主题、表格和虚拟列表。本项目保留其作为后续替代方案；当前没有同负载基准证明其内存、启动时间或扫描速度优于 Tauri，因此不以未经验证的性能假设更换技术栈。

## 第一版范围

- 默认扫描范围为本机所有已挂载、可访问的文件系统磁盘，不要求用户逐个添加。Windows 包括已就绪盘符（本地盘、可移动盘和已映射网络盘），macOS 包括系统数据卷与其他已挂载卷；未挂载的分区、无介质光驱和未映射的远程共享不属于可遍历范围。
- 打开软件后展示默认全盘范围，由用户点击“开始扫描”；不在启动时自动遍历。允许切换为自定义目录扫描。
- 多盘全部进入扫描队列，以受控并发执行，不为每个盘无限扩增线程；单盘不可访问、断开或扫描失败不影响其余盘，结果按磁盘显示状态和错误。
- 切换三类目标、查看当前路径和扫描计数，支持取消。
- 逐步展示结果与大小，支持路径搜索、类型筛选、大小排序和勾选。
- 展示完整路径、所属项目、类型、逻辑大小、目录修改时间、识别依据、统计是否完整。
- 默认不选中任何结果；明确 .venv 是开发环境，不能保证里面没有用户文件。
- 确认清单与体积后移入系统回收站，逐项显示成功或失败。
- 不提供永久删除、后台定时清理、自动管理员提权、远程扫描。
- 不自动清理 Cargo/pip/npm 的全局缓存；第一版仅处理指定的三种目录。

## 现代化界面

采用克制的桌面工具风格：石墨色侧栏、浅色内容区、青绿色强调色、清晰细边框和适量圆角。支持深色与跟随系统主题，使用本机中文字体，路径与容量使用等宽数字。

左侧显示扫描入口、语言类型与设置；主区顶部显示扫描范围、开始/取消按钮、已发现体积和目录数；中部放置搜索与筛选和虚拟结果列表；底部固定选择数量、预计可清理体积和清理按钮。

详细路径与识别依据放在详情面板。空状态、扫描中、大小计算中、取消、部分失败和扫描完成分别展示准确文案。无法提前知道总文件数时显示不定进度，不伪造百分比。

键盘支持焦点导航、空格选择与 Escape 关闭弹窗；支持系统缩放和高 DPI。动画限于短暂状态过渡，尊重减少动态效果设置。

## 核心模块与数据流

- core/model：扫描配置、候选项、事件、错误和清理结果。
- core/scanner：遍历、识别、大小统计、去重与取消。
- core/platform：扫描根目录、排除规则、文件系统链接判断。
- core/cleaner：校验候选项、执行回收站操作、返回逐项结果。
- desktop：Tauri 命令、后台任务状态与 Channel 事件桥接。
- frontend：扫描控制、结果列表、选择状态、确认与反馈。

开始扫描后 Rust 返回扫描任务 ID，后台遍历产生候选项与统计事件，经有界队列与批量推送到前端。每条结果具有稳定 ID，迟到事件根据任务 ID 丢弃。取消后保留已发现结果并标为部分扫描，不允许旧任务覆盖新任务。

扫描与清理互斥。单个应用实例一次只有一个扫描任务或清理任务。用户取消是协作式停止，不承诺中断正在阻塞的操作系统调用。

## 性能设计

- 使用有界工作队列和固定上限的工作线程；初始并发设置保守，按实测调整，不按文件数量创建任务。
- 发现目标后只进行一次大小统计，不再在其内部搜索嵌套清理项，避免 node_modules 内重复结果。
- 扫描根目录规范化并去重，重叠根目录不重复扫描。
- 只读取目录元数据与识别用小文件，不读取依赖文件内容。
- 大小表示普通文件的逻辑字节数，不宣称等于真实磁盘占用或最终释放空间；链接不跟随，硬链接可能造成逻辑大小大于真实占用。
- 大小尚未算完时显示“计算中”；权限等错误导致的部分统计明确标识，不显示为精确值。
- 事件合并后约每 100–200ms 推送，终态必须可靠送达；队列满时合并可丢弃的进度，不丢候选结果。
- 前端仅展示目录结果，虚拟列表仅渲染可见行；不传输每个文件的记录。
- 完成扫描后停止进度计时器，静止页面不持续轮询。

## 识别与清理边界

node_modules 结合父目录 package.json 或自身典型依赖结构确认；target 结合父级 Cargo.toml 或目录中的 Cargo 构建标识确认，兼顾 workspace；.venv 必须包含 pyvenv.cfg。不满足条件的同名目录不进入可清理列表。

第一版不自动读取并解析 Cargo 自定义 target-dir，不扫描任意命名 Python 虚拟环境。这些路径可能不叫 target 或 .venv，超出本版识别范围。

清理仅接受当前内存扫描会话中的候选 ID，不接受界面任意传入的删除路径。执行前重新校验目录类型、目标名称、识别依据与扫描根范围；拒绝根目录、符号链接、Windows junction/reparse point、已变化或无法验证的目标。多个选项去重，不同时清理父子重叠路径。

扫描和清理均跳过链接，不修改目标目录内部文件。执行删除前再次校验仍不能完全消除其他进程同时更改文件树的竞态，不能宣称是面对恶意文件系统变化的安全边界。

回收站失败时保留原目录并报告，不回退永久删除。移入回收站的体积单独显示，不宣称磁盘空间已经释放；真正释放空间取决于用户之后清空回收站。

## Windows 与 macOS

所有核心路径使用 PathBuf/OsString，不通过拼接斜杠操作路径。界面路径仅为展示，不能用展示字符串重新构造清理对象。

Windows：枚举所有已就绪的文件系统盘符，包含固定盘、可移动盘和已映射网络盘；未就绪介质记录为跳过。默认排除 Windows、Program Files、ProgramData、系统回收站及系统卷信息等系统目录；跳过 reparse point，处理被占用文件、拒绝访问、中文路径与长路径错误。

macOS：默认枚举系统数据卷及 /Volumes 下其他已挂载的文件系统卷，包括外置卷和已挂载网络卷；以独立卷根调度扫描，避免系统卷与数据卷映射、卷挂载点产生重复遍历。排除系统目录和废纸篓，跳过符号链接和 Finder 包目录；权限不足记录跳过，不默认请求完全磁盘访问权限。

网络卷和可移动卷可能较慢或在扫描中断开，页面逐盘显示状态，队列保持有界。取消不等待其他磁盘全部结束；底层阻塞 I/O 返回后后台线程再退出，不承诺立即中断操作系统调用。远程或外置文件系统不支持回收站时只报告失败，不回退永久删除。

macOS 保护目录可能需要用户手动给予权限，页面展示具体路径和原因。两平台均使用原生目录选择器及系统回收站适配，不调用拼接路径的 shell 删除命令。

构建目标为 Windows x64、macOS Apple Silicon 与 Intel。Windows 构建与运行在当前环境验证；macOS 使用 macOS runner 构建与自动测试，真实窗口、字体、权限与回收站行为仍须 Mac 实机验收。当前 Windows 环境不能据此宣称已验证 macOS 运行体验。

## 错误与反馈

单目录失败不使整个扫描失败。摘要显示跳过数量与错误分类，详情按需展示，避免大量错误淹没页面。启动失败、无可访问根目录和后台任务异常须有明确终态。删除可能部分成功，每项结果单独更新，不把整批标为成功。

## 验证与验收

核心测试使用临时目录构造三类项目、workspace、同名非目标、嵌套依赖、重叠扫描根、符号链接与取消场景；使用可注入磁盘枚举结果验证多盘全部调度、单盘失败后其余盘继续扫描、挂载点去重。清理校验单独测试，回收站测试仅使用专门生成的临时文件，不清理用户真实依赖。

前端执行类型检查与生产构建；检查大列表滚动、空状态、扫描中与部分失败。性能测量使用 release 构建，记录扫描文件数、目标数、耗时与进程内存；UI 内存应统计整个进程树，不能仅统计 Rust 主进程。分别记录冷缓存与重复扫描，不把操作系统缓存收益归于算法。

不预设未经测量的“几秒全盘扫描”或内存上限承诺。验收要求为：可以真实扫描并取消、无重复目录结果、页面保持可操作、清理只作用于用户确认的有效候选项，平台限制如实展示。
