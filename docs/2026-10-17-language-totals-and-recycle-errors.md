# 0.1.5：类型汇总、右键目录与回收错误

## 类型汇总

左侧分别显示 Node.js、Rust、Python 的目录数与逻辑大小。单次遍历当前候选项进行汇总；同一候选项的大小更新替换原值，搜索或筛选不重复累加。成功回收项不再计入语言及顶部剩余体积，结果列表仍保留已回收标记以便核对。

未扫描显示“等待扫描”；扫描或大小测量尚未结束时标记“统计中”；取消、读取错误或部分结果标记“部分统计”。清理失败后，相关语言及顶部大小标记“待复核”，提示重新扫描以确认当前文件系统状态。数值仍是文件逻辑字节总和，不能当作物理占用或真实释放空间。

## 打开目录

结果行支持右键菜单、Shift+F10、方向键和 Escape。菜单提供“打开目录”和“查看详情”。已确认回收的项目不能再打开目录。

前端仅发送会话和候选 ID；后端拒绝过期会话、未知候选、范围外位置、已消失目录、链接或实际位置变化的路径。普通待统计候选也可以打开；这不放宽清理前完整统计的要求。通过 Rust Opener 接口使用系统文件管理器，没有授予前端通用路径或 URL 打开权限。

## Windows 回收错误

用户报告 `0x80270028`。本机 Windows SDK 绑定将其定义为 `COPYENGINE_E_SHARING_VIOLATION_DEST`，即目标端共享冲突；可能与相关文件被占用有关。参考 [Microsoft Windows 错误常量](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/UI/Shell/constant.COPYENGINE_E_SHARING_VIOLATION_DEST.html)。用户未能回忆原始路径，因此没有定位具体占用进程，也没有操作用户原先失败的目录。

新增共享冲突、访问拒绝、回收大小限制、路径过长、回收站不可用、位置消失及操作取消等中文原因。共享冲突只允许额外一次重试，等待 75ms；要求原项目身份仍一致、未记录成功回收、未触发永久删除拒绝。每次尝试仍使用独立 STA 和原有回收前校验，仍没有永久删除降级。

失败时自动弹出完整路径与原因，并提供打开目录入口；关闭后可从顶部提示再次打开失败列表。统计说明另设标题，与错误信息分开。保留失败项目勾选，便于用户关闭占用程序后自行重试。

## 验证

- Rust 默认核心测试 12 项通过。
- 显式执行 3 项真实回收站测试：仅回收新建临时文件、新建非空中文/逗号目录；新建独占锁文件失败后内容仍保留。没有清理用户真实目录，没有结束用户进程。
- 新目录路径解析测试通过，覆盖待统计的有效候选、范围变化及目录消失。
- 前端 12 项测试通过，包括汇总、超过 4GiB 的加法、部分状态、清理后的扣减、菜单命令参数、键盘菜单、失败路径报告及五种尺寸布局。原生 IPC 在页面测试中模拟，没有把页面测试当作实际 Finder/Explorer 打开验证。
- Clippy 无警告，前端类型检查与生产构建通过。
- Mac 原生文件管理器及回收行为未在本机实测。
